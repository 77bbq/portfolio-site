# 机器人与嵌入式作品集网站设计

## 1. 目标与边界

本项目为一个面向招聘方的中文个人作品集网站。访问者主要通过简历上的二维码进入网站，在手机端快速了解作者的机器人、嵌入式与系统集成经历，并可继续查看项目详情、GitHub、简历和联系方式。

首版只做静态展示，不包含登录、后台管理、评论、数据库、访问统计或在线编辑。文字内容由作者后续在 Markdown 项目文件中补充；站点必须在正文尚未完成时也能正常构建并保持页面完整。

成功标准：

- 扫码后 30 秒内能看懂作者方向、项目阶段和代表项目。
- 研究生项目与本科生项目明确分组，研究生项目优先展示。
- 新增项目只需复制模板、填写数据和放入媒体，不修改页面组件。
- 手机、平板和桌面端均可正常浏览。
- 网站可以部署到 GitHub Pages，并为后续自定义域名和二维码保留稳定入口。

## 3. 技术方案

站点采用 Astro 静态生成、TypeScript、内容集合与 Markdown 项目文件。选择该方案的原因是：

- 输出静态 HTML，适合 GitHub Pages，手机打开速度快。
- 内容与页面组件分离，后续增加项目不需要复制页面代码。
- 内容 Schema 可以在构建时检查必填字段和非法分类。
- 图片可以在构建时生成适合不同屏幕的尺寸。
- 页面默认不需要客户端 JavaScript；只在图库等确有需要的地方加入少量交互。

GitHub Actions 在 `main` 分支更新时构建并发布网站。首选仓库名为 `<github-username>.github.io`，以获得根路径网站；若使用普通仓库名，配置必须支持 GitHub Pages 的子路径。

Astro 配置从环境变量读取 `SITE_URL` 和 `BASE_PATH`：本地开发默认使用 `/`；用户站点仓库使用 `https://<github-username>.github.io` 和空 base；普通项目仓库使用 `https://<github-username>.github.io` 和 `/<repository-name>`。自定义域名上线后改为自定义 `SITE_URL` 和空 base。持续集成除正式配置外，另执行一次 `BASE_PATH=/portfolio` 的构建检查，防止站内链接只在根路径可用。

## 4. 信息架构与浏览路径

首页阅读顺序：

1. 姓名、目标方向和一句定位。身份字段集中存放在站点配置中；默认标题为“机器人与嵌入式作品集”，默认方向为“机器人 · 嵌入式 · 系统集成”，姓名与个人简介为空时隐藏。README 明确标出发布前需要填写的配置位置。
2. 研究生项目区，首先展示“空地协同”。
3. 本科生项目区，展示六个已确认项目。
4. GitHub、简历和联系方式入口。未填写的入口不显示。

项目卡片包含：

- 项目封面或视频海报。
- 中文项目名。
- 学历阶段和项目状态。
- 一句话摘要；为空时不显示。
- 技术标签；为空时不显示。
- 整张卡片可点击进入详情页。

项目详情页阅读顺序：

1. 项目名称、阶段、状态和封面或演示媒体。
2. 一句话成果、本人职责和核心技术的快速信息区；仅显示已填写项目。
3. 项目成果、背景、系统设计、技术难点、测试结果和复盘正文。
4. GitHub、演示视频或文档入口；未填写的入口不显示。
5. 返回相同学历阶段项目区的入口。

项目详情页的稳定路径为 `/projects/<slug>/`。学历阶段只作为数据字段，不进入 URL，避免以后调整分类时使旧链接失效。

## 5. 内容模型

每个项目使用一个独立目录和 `index.md`。Schema 包含：

```yaml
title: "空地协同"
slug: "air-ground-coordination"
stage: "graduate"
status: "ongoing"
order: 10
contentStatus: "placeholder"
summary: ""
cover: "./cover.webp"
coverAlt: "空地协同项目封面"
roles: []
tech: []
metrics: []
media:
  - type: "video"
    src: "/media/projects/air-ground-coordination/demo.mp4"
    poster: "./video-poster.webp"
    alt: "空地协同项目演示视频"
    caption: ""
    order: 10
links:
  repository: ""
  demo: ""
  document: ""
```

字段约束：

- `stage` 仅允许 `graduate` 或 `undergraduate`。
- `status` 仅允许 `ongoing` 或 `completed`。
- `contentStatus` 仅允许 `placeholder` 或 `ready`。
- `slug` 一经公开不随标题或学历阶段变化。
- `order` 按数值升序控制同一阶段内的排序；相同值以稳定 `slug` 升序作为次级排序。
- 摘要、角色、技术、指标和外部链接均可为空；为空时对应界面完全隐藏。
- `cover` 与 `coverAlt` 均可为空；有封面时必须同时提供替代文字，无封面时卡片使用站内统一的中性工程占位图。
- `media` 为可选数组，支持本地 `image` 和 `video`。每项包含稳定顺序、替代文字和可选说明；视频还可包含海报。媒体按 `order` 升序排列，相同值以 `src` 升序作为次级排序。
- 图片媒体使用与项目 Markdown 同目录的 Astro 图片引用；视频媒体使用以 `/media/` 开头的网站根相对公开路径，并在渲染时统一加上 GitHub Pages base。模板和 README 不使用相对于详情页的 `./demo.mp4` 路径，避免普通仓库部署时解析到错误目录。
- `resumeUrl` 与项目链接允许 `https://` 外链、`mailto:` 邮件链接或以 `/` 开头的站内公开路径。站内路径统一加 GitHub Pages base；外链才使用新标签页和 `noopener noreferrer`。其他协议及不带 `/` 的相对路径在构建时拒绝。

首版首页展示全部公开项目，不使用精选过滤。以后项目数量显著增加时再引入精选逻辑，避免首版存在未使用字段和两种相互冲突的展示规则。项目摘要为空时，卡片紧凑显示项目名、阶段和状态，不保留空白区域。

每个 `index.md` 中保留不会渲染到网页的 HTML 注释，提示作者填写以下章节：

- 项目成果
- 项目背景
- 我的职责
- 系统设计
- 核心技术与难点
- 测试结果
- 项目复盘

当 `contentStatus: placeholder` 时，详情页展示媒体、基本信息和“内容整理中”提示，不显示空章节。当作者完成正文后改为 `ready`，正文才公开显示。

## 7. 视觉与交互方向

整体采用克制的工程科技风：深石墨背景、偏冷的蓝色强调色和少量暖色状态提示。视觉重点是真实项目图片、机械结构和硬件细节，而不是霓虹特效或装饰性动画。

- 使用系统中文字体栈，不依赖境外字体服务。
- 首页项目区使用清晰的大标题区分“研究生项目”和“本科生项目”。
- 项目卡片保持统一媒体比例；竖图使用合理裁切，详情页可查看完整图片。
- 手机单列、平板双列、桌面三列。
- 交互不依赖鼠标悬停，整张卡片可点击。
- 可点击区域不小于约 44 像素。
- 动画仅用于轻微进入和状态反馈，并尊重 `prefers-reduced-motion`。
- 颜色、焦点样式和语义结构满足基本无障碍浏览要求。

首版只提供中文界面。内容模型和组件不绑定中文 URL；双语只作为未来可能性记录，不在首版实现任何切换、翻译字段或额外页面。

## 8. 媒体处理

素材处理遵循“原件只读、网站副本可优化”的原则。

- 图片复制到对应项目目录后，以适合网页的方向和构图生成封面版本。
- 超大图片不直接发布；生成响应式 WebP/AVIF 或由 Astro 构建阶段处理。
- 原始比例不适合卡片时，仅裁切封面副本，详情页保留完整图。
- 低分辨率素材不进行夸大式放大；使用克制的版式、背景和最大显示尺寸避免明显失真。
- 视频不自动播放，使用 `controls`、`playsinline` 和延迟加载。
- 机甲大师短视频可以直接托管。
- 空地协同约 23.44 MB 的视频先生成海报并评估压缩；若仍不适合首屏加载，则以海报加点击播放或外部链接呈现。
- PPTX 和 PDF 不直接嵌入首页；可用于提取经确认的封面素材，原文件默认不公开。

所有公开图片和视频需要替代文字或文字说明。团队、学校或比赛素材只展示用户有权公开的内容。

## 9. 容错与隐私

- 缺少可选文字、指标或链接时，页面隐藏对应模块，不渲染空框。
- 缺少项目封面时使用统一的中性工程占位图，不阻断构建。
- 非法学历阶段、重复 slug 或缺少项目名会使构建失败并给出明确错误。
- 所有站内链接使用 GitHub Pages base-aware 路径，兼容根域名和项目子路径。
- 外部链接使用安全属性并提供可见的目标说明。
- 发布前扫描仓库，排除密码、Token、Wi-Fi 信息、客户资料、内部源代码和未经许可的文档。
- GitHub 登录通过浏览器或本机凭据完成，用户无需向聊天提供密码或 Token。

## 10. 验证与验收

实现完成后至少执行：

1. 内容 Schema 检查和 TypeScript/Astro 检查。
2. 生产构建，确认 GitHub Pages 根路径或子路径均可工作。
3. 内部链接和媒体文件存在性检查。
4. 375、768 和 1440 像素宽度的页面检查。
5. 键盘导航、可见焦点、图片替代文字和降低动画偏好检查。
6. 首页确认研究生项目先于本科生项目。
7. `contentStatus: placeholder` 项目确认不会出现空章节。
8. 复制模板新增一个测试项目，确认无需修改组件即可自动分组显示；测试项目不提交到最终版本。
9. 检查视频不自动播放，首页不预加载大视频。
10. 检查仓库中不存在敏感信息和未计划公开的原始文档。

验收结果包括本地可运行源码、七个项目条目、原始素材的优化副本、新项目模板、使用说明和 GitHub Pages 部署工作流。最终发布与二维码生成在用户完成 GitHub 登录并确认公开仓库后进行。
